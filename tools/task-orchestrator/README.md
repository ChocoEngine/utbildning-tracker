# Task orchestrator

Небольшой Kotlin/JVM-инструмент запускает отдельный `codex exec` для каждого
пункта Markdown-чеклиста. Он не привязан к функциональному плану приложения:
можно передать любой файл и регулярное выражение идентификаторов задач.
Для сборки используется JDK 17, как и для Android-проекта.

## Запуск для очереди F

Из корня репозитория:

```bash
tracker-app/gradlew -p tools/task-orchestrator run --args="--project ../.. --plan FEATURE_PLAN.md --task-pattern F\\d+ --commit-each"
```

Сначала рекомендуется проверить рассчитанный порядок без запуска Codex:

```bash
tracker-app/gradlew -p tools/task-orchestrator run --args="--project ../.. --plan FEATURE_PLAN.md --task-pattern F\\d+ --dry-run"
```

По умолчанию задачи выполняются строго по порядку в плане. Новый `codex exec`
запускается только после успешного завершения предыдущего и появления `[x]` у
его пункта. Частичный результат, блокировка, ошибка процесса или незакрытый
чекбокс останавливают очередь. С `--commit-each` оркестратор сам создаёт отдельный
commit после успешного шага и только затем переходит дальше; агенту прямой commit,
push и PR запрещены базовым промптом.

Логи JSONL сохраняются в `.codex-orchestrator/runs/`.
Файловая блокировка не позволяет случайно запустить две очереди для одного
проекта одновременно. Если автономному запуску требуется автоматическое
рассмотрение запросов доступа, это включается явно флагом `--approve-for-me`;
режим sandbox остаётся `workspace-write`.

`--commit-each` требует чистого Git checkout перед запуском. После выполнения
задачи агент возвращает короткий английский commit subject; оркестратор проверяет,
что агент не создал commit самостоятельно, выполняет `git add -A`, создаёт commit
и снова проверяет чистоту checkout. Ошибочный или частичный шаг не коммитится.

## Произвольный план

Поддерживается форма:

```markdown
- [ ] **T01 — Название.** Полное описание и критерии.
  <!-- codex-task: depends-on=T00; parallel-safe=true -->
```

Параметры метаданных необязательны:

- `depends-on` — идентификаторы зависимостей через запятую;
- `parallel-safe=true` — задачу разрешено включить в параллельную волну.

`--ordering ordered` добавляет каждой задаче зависимость от предыдущей.
`--ordering dependencies` использует только явно указанные зависимости.

## Параллельный режим

Параллельный запуск требует одновременно `--parallelism N` и `--worktree`:

```bash
tracker-app/gradlew -p tools/task-orchestrator run --args="--project ../.. --plan tasks.md --task-pattern T\\d+ --ordering dependencies --parallelism 2 --worktree"
```

Каждая задача выполняется в отдельном managed Git worktree. Перед стартом
checkout должен быть чистым. После одной параллельной волны инструмент
останавливается и печатает идентификаторы Codex threads: результаты требуется
просмотреть и интегрировать вручную. Автоматическое слияние намеренно не
реализовано, потому что оно требует политики коммитов и разрешения конфликтов.

Для просмотра всех рассчитанных волн без создания worktree используйте
`--dry-run`; для ограничения одной или несколькими задачами — `--max-tasks N`.
