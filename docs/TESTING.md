# Тесты проекта

Имена классов и методов описывают поведение приложения, а не номер задачи или
этап разработки. Номера версий в тестах миграций — версии схемы Room.

## Состав

- `tracker-app/app/src/test/`: 36 JVM-тестов правил расписания, пересечений,
  редактирования тем, темпа, локальных суток и хранения истории.
- `tracker-app/app/src/androidTest/`: 249 методов, включая проверки Room,
  репозитория, резервных копий, UI, уведомлений и вспомогательные сценарии.
- `tools/task-orchestrator/src/test/`: 9 тестов отдельной утилиты оркестрации.

Исторические `.kt`-материалы в `docs/review/` не входят в исходные наборы
Gradle и сохранены как свидетельства прежних расследований.

Число методов не равно числу проверенных условий: часть тестов содержит матрицу
RU/EN или состояний. Assumption-пропуск не является успешной проверкой.

Проверки разных уровней сохраняются отдельно: JVM проверяет чистое правило,
репозиторий — транзакции и хранение, UI — доступность действия и взаимодействие.
Проверки старых схем Room нужны для обновления существующей установки.
`CourseLifecyclePersistenceTest` и `BackupLifecycleIntegrationTest` проверяют
составные сценарии с повторным открытием файловой БД; они дополняют отдельные
проверки операций.

## Обычный прогон

Из `tracker-app/`, JDK 17 и установленный Android SDK:

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug --console=plain
./gradlew :app:connectedDebugAndroidTest --console=plain
```

Instrumentation запускать на отдельном эмуляторе: некоторые сценарии меняют
рабочую БД, язык приложения, разрешения и доставляют реальные уведомления.
Не подключать пользовательское устройство к полному прогону.

Утилита оркестрации проверяется отдельно, из корня репозитория:

```sh
tracker-app/gradlew -p tools/task-orchestrator test --console=plain
```

## Специальные сценарии

`OvernightAlarmDeliveryTest` и `OpenMidnightTest` требуют отдельного запуска
около полуночи; обычный прогон пропускает их по assumptions. Полный обычный
прогон не доказывает доставку ночью, reboot или работу на другой версии Android.
`ReminderRecoveryTest` по умолчанию проверяет идемпотентность восстановления;
реальный reboot и смена разрешений требуют внешних действий между фазами
`recovery_phase` (`prepare`, `denied`, `clicked_skipped`, `cleanup`).

`EmulatorDemoSeedTest`, `EmulatorLongTitleSeedTest` и
`EmulatorAcceptanceSeedTest` — явное наполнение эмулятора, не регрессии продукта.
Без аргументов они пропускаются. Аргументы включения: `seedDemo=true`,
`keepThreeDemo=true`, `seedLongTitle=true`, `seedAcceptance=true`.
Существующий `scripts/seed-emulator.sh` использует демо-набор.

Визуальные классы создают артефакты RU/EN; снимок сам по себе не доказывает
корректность изображения. Геометрические и поведенческие assertions действуют
автоматически, внешний вид требует просмотра. Общие функции ожидания отрисовки
и записи MediaStore находятся в `ui/TestScreenshots.kt`; окно с IME снимается
через реальный экран, а не только Compose-узел.

## Переименования

| Прежний класс | Текущий класс |
|---|---|
| `R05EditorReviewTest` | `CourseEditorKeyboardTest` |
| `R05EmulatorSeedTest` | `EmulatorAcceptanceSeedTest` |
| `MvpScenarioTest` | `CourseLifecyclePersistenceTest` |
| `FunctionalAcceptanceTest` | `BackupLifecycleIntegrationTest` |
| `RecoveryProbeTest` | `ReminderRecoveryTest` |

Для наполнения приёмочного эмулятора вместо `seedR05=true` использовать
`seedAcceptance=true`. Идентификаторы уже сохранённого fixture не менялись,
чтобы повторное наполнение не создавало дубли. Датированные отчёты и логи
сохраняют прежние команды и имена как свидетельства тех запусков.

## Чистка 2026-10-18

- Удалён `NavigationEntryFlowTest`: он проверял только внутреннее поведение
  AndroidX NavController без вызовов приложения. Сквозные `AppNavigationTest`
  сохранены; их три Kotlin `assert` заменены обязательными JUnit `assertTrue`.
- Удалён повторный тест очистки списка тем; его проверки отсутствия календаря
  перенесены в `emptyListIsAllowedAndCompletedTopicsRemain`.
- Удалён репозиторный «тест отмены», который только вызывал чистый планировщик
  списка. Неизменность входа проверяется `TopicListEditorTest`, реальная отмена
  окна — `CoursesScreenTest`.
- Убраны повторные итерации одинаковых курсов без расписания из ручного
  прохождения и проверки жестов; старые «оба режима» больше не существуют.
- Проверка возобновления без расписания перенесена из визуального класса в
  `ScheduleRepositoryTest` и использует фиксированные часы.
- Убраны повторные и заведомо истинные assertions. Проверка смены имени/цвета
  сверяет все проекции занятий, включая прошлые и отмеченные.
- Полный прогон выявил пять тайм-аутов выбора категории: при открытой IME
  список скрыт, но его semantics-узлы существуют. Снимок перед падением
  подтвердил скрытый список. `TestInteractions.selectCategoryOption` явно
  закрывает видимую IME кнопкой Back, прокручивает строку и ждёт её видимости
  до нажатия. Проверки сохранения категории не ослаблены, тайм-ауты не увеличены.
- В сценарии длинного clipboard-ввода убран повторный цикл «вставить — отменить».
  Отмена остаётся в отдельном UI-тесте; здесь сохранены проверки полного текста,
  отсутствия записи до применения и сохранения нормализованного результата.
- Названия об архивировании тем, отдельных резервах цветов и старом карандаше
  расписания заменены описанием проверяемого поведения текущей схемы/UI.
