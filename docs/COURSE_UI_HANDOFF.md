- `ui/AppNavigation.kt`: обработчик выхода из курса перед переключением нижней навигации.
- `ui/today/TodayScreen.kt`: убран текст заголовка «Сегодня», дата остаётся.
- `ui/theme/Color.kt`: пробные новые оттенки №4 и №7; палитра и макеты пока не синхронизированы, визуального согласования нет.
- `data/TrackerRepository.kt`: ограничение названия курса 50 Unicode code points и отдельная ошибка; категории этим ограничением не затронуты.
- `tracker-app/app/src/main/res/values/course_strings.xml` и `values-ru/course_strings.xml`: строки продолжения и ошибки длины.
- `tracker-app/app/src/androidTest/java/com/utbildning/tracker/ui/CoursesScreenTest.kt` и `CourseDraftRecreationTest.kt`: начата адаптация под новый сценарий, **не запускались после правок**.

## С чего продолжить

**Приоритетная проблема со слов пользователя:** не было видно кнопки расписания. Вход был малозаметным текстом ниже выбора цвета и режима. Он заменён полноширинной кнопкой «Настроить расписание» сразу под категорией. Для активного нового и существующего курса сквозной путь проверен на API 36; кнопка теперь заметна до палитры и списка тем. Приостановленный курс остаётся без этой кнопки согласно отложенному сценарию возобновления.

### Результат последующего расследования 2026-09-26

На API 36 сквозные проверки создания нового курса и настройки существующего активного курса без расписания проходят. Проверены открытие формы, выбор дня, сохранение, создание занятий, отмена до сохранения, пересоздание Activity и отсутствие дублей; `AppNavigationTest`: 4/4 после изменений. Полный прогон из 104 тестов до последней UI-правки: 103 прошли, одна несвязанная ошибка локали в `CoursesScreenTest`. `ScheduleScreenTest` и `ScheduleRepositoryTest` прошли. `ReminderNavigationTest` отдельно подтвердил exact alarm и доставку при прямом сохранении с ручным `reconcile`; установку alarm после сохранения через UI отдельно не проверяли. Сквозные тесты — в `tracker-app/app/src/androidTest/java/com/utbildning/tracker/ui/AppNavigationTest.kt`.

1. Проверить дифф начатой реализации, особенно `CoursesViewModel`: автосохранение не должно терять быстрые изменения, сохранять соседние поля устаревшим снимком или скрывать ошибку выходом. Есть дублирование загрузки/наблюдения в `open` и `attach`; сначала проверить поведение, не делать общий рефакторинг.
2. Проверить границы создания: до выбора режима только черновик; по расписанию создаётся после выбора режима, без расписания — после применения непустых тем. Проверить лимит/категорию/цвет при отмене и ошибке.
3. Проверить сохранение названия и категории на потере фокуса, Back, нижней навигации и переходе к расписанию. Уход приложения в фон пока специально не обработан. Проверить invalid-name + фокус/выход/действия завершения, а также удаление выбранной категории при активном поле, чтобы не создать её вновь.
4. Актуализировать весь затронутый набор тестов, а не только два изменённых файла; визуальные тесты и гайд могут ещё ожидать прежний общий Save. Не снимать защиту данных ради прохождения старых ожиданий.
5. После разрешённого запуска проверок исправить найденное и выполнить визуальную приёмку RU/EN, сохранить снимки. Отдельно синхронизировать новую палитру, макеты и гайд. Обновить статусы только по фактическому результату.
