# Упрощение хранения прохождения тем

Реализуй упрощение модели прохождения тем в Android-проекте `tracker-app/`. Перед изменениями прочитай `AGENTS.md`, актуальные сущности Room и относящиеся к задаче операции репозитория. Сохрани посторонние изменения, включая незавершённую переработку редактора курса. Не создавай тикет, не коммить и не пушь.

## Согласованное поведение

- У одного курса предусмотрено не более одного занятия в день.
- Пользователь может изменять результат только сегодняшнего занятия. Это новое требование заменяет прежнее разрешение исправлять прошлые результаты в календаре. Прошлые занятия остаются доступны для просмотра.
- Отдельная история тем по занятиям и снимки названий тем больше не нужны.
- Прохождение хранится непосредственно в теме двумя полями: `isCompleted: Boolean` и `completionDate: Long?`.
- `completionDate` — локальная календарная дата занятия в том же формате, что `sessions.date`, а не timestamp отметки.

Состояния темы:

| Действие | isCompleted | completionDate |
|---|---|---|
| Создание темы | false | null |
| Ручная отметка из курса | true | null |
| Отметка через сегодняшнее занятие | true | дата занятия |
| Снятие прохождения | false | null |

При сбросе результата сегодняшнего занятия из `DONE` в `PENDING` или `SKIPPED` снять прохождение только тем этого курса с `completionDate`, равной дате занятия. Ручные отметки с `null` сохранить. Не присваивать дату занятия уже пройденным вручную темам. Если пользователь снимает отметку темы и заново отмечает её из курса, она становится ручной: `true / null`.

При изменении выбранных тем уже отмеченного сегодняшнего занятия согласованно обновлять только его отметки; темы, снятые из выбора, перестают быть пройденными, добавленные получают дату занятия. Повторное сохранение должно быть идемпотентным. Не вводить новый интерфейс редактирования выбора, если его сейчас нет.

Ручное завершение курса отмечает непройденные темы как `true / null`, сохраняя происхождение уже пройденных тем. Остальные правила завершения, паузы, переключения режима, генерации занятий и уведомлений сохранить.

## Объём изменений

1. Проверь актуальный путь чтения и записи прогресса в `data/local/Entities.kt`, `TrackerDao.kt`, `TrackerDatabase.kt`, `data/TrackerRepository.kt` и `data/TrackerOperations.kt`, а также вызывающие их UI-компоненты. Найди все обращения к `topic_completions` и `session_topic_history`.
2. Добавь поля прохождения в `TopicEntity`. Удали таблицы `topic_completions` и `session_topic_history`, связанные сущности, DAO-методы и зависимости после переноса всех потребителей. Не добавляй вместо них `sessionId`, источник прохождения или другую таблицу истории.
3. Перепиши вычисление прогресса, выбор непройденных тем, ручную отметку, результат занятия и завершение курса на новую модель. Не меняй порядок и идентификаторы тем, правила редактирования списка и сохранение прогресса неизменённых тем.
4. Ограничь исправление результатов сегодняшней локальной датой и в UI, и на уровне операции записи. Дату вычисляй по существующему контракту часового пояса; не сравнивай timestamp с календарной датой. Не блокируй автоматическую обработку прошлых `PENDING` как `SKIPPED`.
5. Добавь миграцию Room с текущей версии на следующую и обнови экспорт схемы. Сначала перенеси данные, затем удали старые таблицы в безопасном порядке. Без destructive migration.
6. Для каждой существующей темы наличие записи `topic_completions` означает `isCompleted = true`. Для `source = SESSION` возьми `completionDate` из связанного занятия; для `MANUAL` и `COURSE_COMPLETION` оставь `null`. Темы без записи получают `false / null`. Не восстанавливай текущее прохождение из исторических записей: они не являются источником актуального прогресса.
7. Сохрани категории, курсы, расписания, занятия и их результаты, архивные темы и текущий прогресс. Не очищай пользовательские данные. Обнови относящиеся к изменению документы и HTML-схему БД, если она присутствует.

## Проверка и приёмка

Добавь или адаптируй целевые проверки:

- Миграция сохраняет актуальное прохождение для всех трёх прежних источников; непройденные темы остаются непройденными, история без актуального completion не восстанавливает отметку.
- Новая тема имеет `false / null`; ручная отметка и повторная ручная отметка после снятия дают `true / null`.
- Через занятие дата присваивается только выбранным непройденным темам этого курса.
- Сброс сегодняшнего занятия снимает только его отметки, сохраняет ручные отметки, другие курсы и отметки прошлых дат.
- Повторное сохранение результата не меняет прогресс повторно. Изменение выбора тем, если поддерживается существующим UI, корректно обновляет отметки.
- Изменить прошлое или будущее занятие через пользовательскую операцию нельзя; просмотр истории и автоматическое закрытие прошедших неотмеченных занятий работают.
- Редактирование списка тем, ручное завершение и переключение режима сохраняют согласованный прогресс.

Запусти сборку и относящиеся к задаче JVM/Room-инструментальные проверки по инструкциям проекта. Если запускаешь эмулятор, используй предусмотренное повторяемое заполнение, сохраняя пользовательские данные. Не запускай отложенную проверку Android 13 или работы S25.
