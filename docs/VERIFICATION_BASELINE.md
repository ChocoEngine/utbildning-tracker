## L02–L03, 2026-10-22

Проверки выполнены в ветке `codex/version-02` поверх
`2e2957ad79ca7b149899375bfc3da375fdcf5c53`. Один `BackupArchive.validate()` служит импорту и
JVM-тесту. Сохранённый [синтетический эталон v1](../tracker-app/app/src/test/resources/backup/README.md)
создан Python `zipfile` по контракту при этой ревизии, без производственного
сериализатора. Текущий reader прочитал все переносимые поля; текущий writer
сделал round-trip; изменённый major был отклонён.

Из `tracker-app/` на JDK 17 выполнено:

```sh
./gradlew :app:testDebugUnitTest --tests 'com.utbildning.tracker.backup.*' :app:assembleDebug :app:lintDebug --console=plain
./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.package=com.utbildning.tracker.backup --console=plain
```

JVM: 13/13, 0 failures и пропусков; направленный Android-набор на отдельном
`F17_API_36` (API 36): 17/17, 0 failures и пропусков. Android-тест проверил,
что повреждение, неподдерживаемая версия и потерянная ссылка отклоняются до
изменения данных и `committedBackupId`. Сборка debug и lint завершились успешно;
lint сообщил 0 errors и 43 warnings. Исходные U01–U03 правки в рабочем дереве
сохранены. Не выполнялись полный instrumentation, API 33, физическое устройство
и пользовательская проверка. Пользователь подтвердил, что старой копии нет;
получение экспорта прежней ревизии исключено из текущего плана. L03 завершён
по проверенным критериям сохранённого v1-эталона и текущего round-trip, без
утверждения о фактической межверсионной проверке.

Дополнительно на том же отдельном `F17_API_36` установлен APK
`app-debug.apk` (SHA-256 `a863cc021282036cc2e0cbaa403bce1ac07668e26e92f530d66c580534ce32ae`).
Через Settings → Restore backup → системный выбор файла Downloads выбран

экранного пути и БД на эмуляторе; происхождение прежнего экспорта и

## Что не нужно начинать повторно

- Реализацию MVP, F01–F17, PERF-01–07 и U01–U03; их принятые правила записаны в
  [действующем ТЗ](PRODUCT_SPEC.md). QA-001 и R01–R06 закрыты в заявленном
  объёме. Старые номера задач и отчёты не являются новой очередью.
- Отдельный перенос одного занятия, сброс прогресса при изменении расписания,
  экран управления категориями в настройках и восстановление старых HTML-макетов:
  эти варианты исключены из текущих договорённостей.
- Повторять старые прогоны только ради воспроизведения чисел. Для изменённой
  версии нужны **новые** проверки по [открытому плану](OPEN_WORK.md), включая
  R07 и последующую независимую пользовательскую приёмку.

Следующее подтверждение записывать здесь с точной ревизией, APK, устройством/API,
числом успехов/failures/пропусков и непроверенными сценариями. Успех одной
подсистемы не расширяет автоматически объём проверки на остальные.
