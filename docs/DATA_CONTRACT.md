# Контракт данных — схема 2

Корень приложения: `tracker-app/`; пакет `com.utbildning.tracker.data.local`.
Room / SQLite, внешние ключи включены, экспорт схемы обязателен. S04 создаёт
сущности, DAO и открытие БД; бизнес-транзакции курсов, отметок и расписаний
реализуются в репозитории S05/S06/S08/S11/S13/S18, а не в UI.

## Сущности и ключи

Идентификаторы — непустые строки (UUID в операциях создания репозитория).
Временные метки — epoch milliseconds UTC (`Long`),
локальные даты — `LocalDate.toEpochDay()`, время — минуты от начала суток.
Никаких зависимых от языка строк дат. Enum сохраняются именами, не ordinal.

- `categories`: `id`, `name`.
- `courses`: `id`, `name`, `colorId` (0–9), nullable `categoryId`,
  `mode` (`SCHEDULED`/`UNSCHEDULED`), `isCompleted`, `isPaused`,
  `createdAt`, `updatedAt`, nullable `completedAt`, nullable `exhaustedAt`,
  `completionPromptDismissed` (по умолчанию false). Категория удаляется
  с SET NULL в курсах; удаление курса каскадно удаляет принадлежащие ему данные.
- `color_reservations`: `colorId` PK, `courseId` UNIQUE/FK CASCADE.
  Цвет незавершённого курса резервируется независимо от паузы и режима.
  Сохранённый `courses.colorId` не зависит от освобождения резерва.
  Создание и редактирование S05 согласуют цвет и резерв в одной транзакции
  и проверяют лимит 10; освобождение при завершении относится к S18.
- `topics`: `id`, `courseId`, `position`, `title`, nullable `archivedAt`.
  Порядок не уникален на уровне БД, чтобы перестановка могла выполняться
  транзакцией без временного нарушения UNIQUE; сортировка `position, id`.
  Удаление темы редактором S06 — архивирование, чтобы не потерять
  исторические ссылки. Окончательное удаление происходит вместе с курсом.
  DAO S04 возвращает в `getTopics`/`observeTopics` также архивные строки;
  редактор S06 исключает их; знаменатель прогресса также должен исключать их.
- `schedules`: `courseId` PK/FK, `startsOn`, nullable `endsOn`, nullable
  `generatedThrough` (последняя обработанная дата, не будущий водораздел истории),
  nullable `generationNotBefore` (epoch milliseconds, начало первой/возобновлённой генерации).
  Один текущий календарный план на курс. S11 запрещает его для UNSCHEDULED.
- `schedule_rules`: `(courseId, dayOfWeek)` PK/FK к schedules; день ISO 1–7,
  `startMinute`, nullable `endMinute`, `endDayOffset` (0/1).
  Допустимость ночного занятия, DST и часовой пояс уточняются до генератора S10.
- `sessions`: `id`, `courseId`, `date`, `startMinute`, nullable `endMinute`,
  `endDayOffset`, `result` (`PENDING`/`DONE`/`SKIPPED`),
  `createdAt`, `updatedAt`.
  UNIQUE `(courseId,date,startMinute)` исключает повторную генерацию.
  Сессия не ссылается на текущее расписание: его удаление не стирает историю.
  Название и цвет всегда читаются из текущего курса через JOIN. Схема v3
  удаляет снимки имени/цвета; миграция сохраняет занятия, историю и прохождение тем.
- `session_topic_history`: `(sessionId,topicId)` PK, `courseId`,
  `topicTitleSnapshot`, `recordedAt`. Это факт того, что тема была отмечена на
  занятии, а не действующая отметка. Повторная обработка не создаёт дубль.
  Факт сохраняется при снятии отметки, переименовании/архивировании темы
  и исправлении результата; это не журнал всех редакций.
- `topic_completions`: `topicId` PK, `courseId`, `source`
  (`MANUAL`/`SESSION`/`COURSE_COMPLETION`), nullable `sessionId`, `completedAt`.
  Отсутствие строки = тема не пройдена. Одна строка = один действующий источник.
  SESSION требует sessionId, прочие источники требуют null.

Составные FK истории к `(id,courseId)` занятия и темы запрещают связь между
разными курсами. Действующая отметка ссылается на `(id,courseId)` темы и,
для SESSION, на `(sessionId,topicId,courseId)` исторического факта.
История сама по себе никогда не участвует в подсчёте текущего прогресса.
Курс удаляет всё каскадно; удаление расписания удаляет только недельные правила.

## Операции курсов и категорий (S05)

`data/TrackerRepository.kt` — граница записи для будущего UI. Создание курса,
его начальных тем, категории и резерва цвета выполняется одной `withTransaction`.
Лимит — 10 строк `courses` с `isCompleted = false`, включая паузу и оба режима.
Цвет — 0–9; резерв принадлежит одному незавершённому курсу. Ошибка в любой
вставке откатывает всю операцию, включая новую категорию. UUID и время
предоставляются репозиторием; для тестов генератор и часы можно подменить.

Название курса и названия тем обрезаются по краям; пустое название курса
или пустая тема недопустимы. `UNSCHEDULED` требует хотя бы одну тему;
`SCHEDULED` допускает пустой список. Это API готового списка: разбор текстового
блока с пропуском пустых строк предоставляет `TopicListEditor.parse` (S06).
Режим существующего курса не меняется через API редактирования.

Поле категории обрезается по краям: пустое значение снимает категорию,
точное совпадение без учёта регистра выбирает существующую, иначе создаётся
новая. Сравнение выполняется в Kotlin с `ignoreCase`, в том числе для кириллицы,
а не через ограниченный ASCII SQLite `NOCASE`. Выбор другой категории меняет
только редактируемый курс. Отдельная операция `renameCategory` переименовывает
общую категорию и отвергает совпадение с другой категорией. Наблюдение за
списками через Flow и получение доступных цветов ничего не создают.

Редактирование незавершённого курса допускает собственный цвет даже при
достигнутом лимите; замена резерва атомарна. Завершённый курс сохраняет свой
цвет без резерва и без возможности перекрашивания. `availableColors` возвращает
свободные цвета и текущий для незавершённого, только сохранённый для завершённого.
Изменения названия/цвета курса сразу отражаются во всех занятиях, включая прошлые. Завершение, пауза и удаление курса — отдельные операции S18.

Ошибки правил представлены `RepositoryException` с кодом `RepositoryError`;
будущий UI должен сопоставить коды локализованным ресурсам. Ошибки хранения
и отмена корутины не маскируются под ошибки пользовательского ввода.

## Редактор списка тем (S06)

`domain/TopicListEditor.kt` — чистый разбор и план изменений без Room и записи.
LF, CRLF и CR разделяют строки; крайние пробелы удаляются, пустые строки
пропускаются. Номер строки остаётся исходным, начиная с 1. Перенос отображения
в UI не добавляет разделителя. `parse` пригоден также для списка нового курса.

`EditableTopic` — снимок ID, названия, позиции, признаков прохождения и архива.
`editableText` включает только активные непройденные темы по `position, id`.
`plan` проверяет каждую непустую строку против активных пройденных тем:
полное совпадение после trim с `ignoreCase` (включая кириллицу) вызывает
`TopicListConflictException.lineNumbers` со всеми исходными номерами строк.
Конфликт ничего не удаляет. Архивные темы не участвуют ни в проверке,
ни в сопоставлении, ни в видимом списке.

Для сохранения ID строки сопоставляются с активными непройденными темами
по точному названию после trim, с учётом регистра. При одинаковых названиях
старые темы берутся FIFO по `position, id`; новые строки — сверху вниз.
Дубли не схлопываются. Лишние строки получают новый ID при сохранении,
лишние старые темы архивируются. Переименование, включая смену регистра,
означает архивирование старой темы и создание новой; история остаётся у
старого ID. Перестановка и крайние пробелы ID не меняют.

Пройденные темы, их позиции, отметки и история остаются неизменными.
Редактируемым строкам назначаются возрастающие позиции с 0, пропуская
позиции пройденных тем. Поэтому порядок непройденных соответствует тексту,
а в общем списке между ними могут остаться пройденные темы.

`getTopicEditorTopics` читает согласованный снимок в транзакции. Подготовка
и применение плана к локальному черновику ничего не пишут в БД; отмена —
отбрасывание черновика. Единственная запись — `saveTopicList(courseId, text)`:
она заново читает темы и действующие отметки и строит план в одной транзакции,
проверяет существование и незавершённость курса, затем архивирует удалённые,
обновляет сохранённые и вставляет новые темы. Для UNSCHEDULED итоговый
активный список (включая пройденные) непуст; SCHEDULED допускает пустой.
Завершённый курс отвергается с `COURSE_COMPLETED`, пустой список без
расписания — `TOPICS_REQUIRED`. Ошибка откатывает все записи и `updatedAt`
курса. Метод возвращает активные темы по `position, id`; результаты и прохождение
не меняет. Появление непройденной темы возобновляет приостановленную генерацию
с текущего момента по контракту S18. Повторное сохранение идентичного
состояния не меняет `updatedAt`.

## Владение прохождением и транзакции

Все перечисленные ниже изменения выполняются одной Room-транзакцией
репозитория. DAO — примитивы хранения; прямого доступа из UI нет.
Физическое удаление отметки не удаляет исторический факт. Не использовать
REPLACE для родительских сущностей: оно может запустить каскадное удаление.

| Действие | Изменение текущего прохождения | История / результат |
|---|---|---|
| Ручная отметка непройденной темы | вставить MANUAL | занятия не создаются |
| Ручное снятие любой отметки | удалить topic_completions этой темы | факт SESSION и результат занятия остаются |
| PENDING/SKIPPED → DONE с явным набором тем | добавить SESSION только для непройденных тем | записать недостающие факты, DONE даже при пустом наборе |
| DONE → DONE, исправить набор | убрать только свои SESSION, исключённые из нового набора; добавить новые допустимые | чужие MANUAL/SESSION/COURSE_COMPLETION не менять; факты сохранять |
| DONE → SKIPPED/PENDING | убрать только текущие SESSION данного занятия | результат изменить; факты сохранить |
| Снятие своего SESSION в уже завершённом курсе | заменить только снимаемый источник на COURSE_COMPLETION с completedAt курса | история остаётся; курс и все темы остаются завершёнными |
| PENDING ↔ SKIPPED | не менять прохождение | изменить только результат |
| Повтор того же результата без явного редактирования тем | не восстанавливать отметки по старой истории | идемпотентно |
| Завершение курса | оставшиеся непройденные темы → COURSE_COMPLETION | результаты прошлого календаря не меняются |

Пример: A завершило тему → ручное снятие → B завершило тему. Исправление A
не удаляет вклад B; снятие отметки B не позволяет A закрыть тему снова по
устаревшей истории. Явный новый выбор непройденной темы на A разрешён; его
нельзя выводить автоматически из старой связи. Редактор результата предвыбирает
только текущие отметки SESSION данного занятия, не всю историю.

Состояние завершения курса отдельно от источника темы; ручное завершение
не должно заменять действующие источники уже пройденных тем. Отказ завершить
курс после последней темы и границы удаления будущих занятий — S18 совместно
с контрактом генерации S10, без автоматического восстановления отменённых дат.

## Форма курса и ручное прохождение (S07–S08)

`saveCourseForm` объединяет метаданные, категорию, резерв цвета и список тем
в одной внешней транзакции. Конфликт списка откатывает также имя, новую категорию
и смену цвета. `topicText = null` сохраняет список без изменений; в завершённом
курсе переданный текст не применяется. Существующий режим остаётся неизменным.
`CourseDetails` читает курс, категорию, активные темы и текущие отметки одним
снимком транзакции; Flow перечитывает его при изменениях соответствующих таблиц.

Удаление категории — отдельная транзакция, независимая от черновика формы.
При наличии любых курсов, включая завершённые, требуется `confirmed = true`;
иначе возвращается `CATEGORY_IN_USE`. Внешний ключ SET NULL сохраняет курсы,
темы, прохождение и календарь. UI сбрасывает выбранную удалённую категорию.

`toggleTopicCompletion` разрешён для активной темы незавершённого курса обоих
режимов. Отсутствующая отметка становится MANUAL; существующая удаляется независимо
от её источника. История и результат занятия не меняются, фиктивное занятие
для ручной отметки не создаётся. Снятие последней отметки исчерпанного списка
возобновляет обычную генерацию будущих занятий с текущего момента.
Архивная тема, чужой курс и завершённый курс отвергаются. Метка изменения курса
обновляется в той же транзакции, автоматического завершения здесь нет.

## Границы защиты

SQLite проверяет PK/UNIQUE/FK и каскады. Kotlin-конструкторы проверяют диапазоны
цветов/дней/времени и согласование source/sessionId. Эти проверки не являются
SQL CHECK и не защищают от произвольного raw SQL. Межтабличные бизнес-правила
(например, SESSION только для DONE, запрет расписания UNSCHEDULED, резерв
только у незавершённых) проверяет репозиторий. Генерация, исправление результатов,
пауза и завершение реализованы в TrackerOperations; прямой вызов DAO не заменяет
эти операции и не обеспечивает их бизнес-инварианты.

`TrackerDatabase.open(context, name)` открывает файловую БД через applicationContext.
Никаких destructive migrations; схемы сохраняются в `app/schemas/`.
Миграция 1→2 добавляет exhaustedAt, completionPromptDismissed и generationNotBefore;
существующие курсы, темы, расписания и история сохраняются. Отдельный тест создаёт
файл по экспортированной схеме v1, открывает через Room v2 и проверяет данные.
Следующее изменение опубликованной схемы требует миграции и отдельного теста.

Отложенная очистка календаря после MVP потребует сначала сохранить действующие
SESSION-отметки как независимое прохождение: простое удаление сессий/истории
каскадно удалит связанные текущие отметки. S04 такой очистки не предоставляет.
