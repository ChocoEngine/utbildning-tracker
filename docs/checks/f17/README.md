# F17 — сквозная проверка и гайд

Выполнено 2026-10-08. Функциональная очередь F01–F17 принята; S25 в эту
проверку не входила.

## Сквозной сценарий

Добавлен `FunctionalAcceptanceTest` с отдельной файловой БД и двумя настоящими
ZIP+JSON v1 архивами. Один набор данных прошёл цепочку:

1. старая английская копия активного курса с категорией, цветом, прогрессом,
   расписанием и историей;
2. пауза и продолжение с сохранением истории, цвета и прохождения;
3. завершение с освобождением цвета и последующий перезапуск с первым свободным
   цветом, пустыми прогрессом, историей и расписанием;
4. включение расписания, отметка занятия и темы, отключение с сохранением
   результата и прогресса, затем повторное включение;
5. очистка по локальной границе: старое занятие удалено, тема, цвет, расписание
   и будущий календарь сохранены;
6. новая русская копия, последовательное восстановление старой и новой копий;
7. закрытие и повторное открытие Room, очистка старой дедупликации уведомлений,
   построение актуальных кандидатов и две синхронизации без дублей.

Отдельный миграционный тест создаёт реальную БД по экспортированной схеме v7,
открывает её текущим приложением как v8 и проверяет категорию, курс, тему,
расписание, правило, занятие, внешние ключи и пустое внутреннее состояние
восстановления. Старые проверки миграций v4/v5 обновлены до фактической v8.

Полный прогон выявил не продуктовый дефект, а неверную тестовую модель действий
шторки: тест создавал два занятия одного курса в одну дату, хотя приложение
генерирует не более одного. Матрица перестроена на отдельный курс и занятие для
каждого ответа; повторное открытие шторки и пересоздание RU/EN-ресурсов теперь
явны. Продуктовый код не менялся.

## Гайд

RU/EN-гайд теперь рекомендует сделать свежую копию перед перезапуском курса,
уменьшением срока истории или переносом телефона и сохранить прежнюю проверенную
копию. Уточнено, что после восстановления на другом устройстве нужно снова
выбрать папку еженедельных копий и проверить разрешения уведомлений: эти
локальные настройки не переносятся. README обновлён до Room v8 и этого отчёта.

## Известные ограничения

- Android 13 не запускался по прежнему решению пользователя; проверка выполнена
  на Android 16 / API 36.
- Не ожидались реальные семь дней до фоновой копии и сутки до очистки; проверены
  WorkManager-контракты и прямые запуски операций.
- Не моделировалось системное убийство процесса ровно во время ZIP-записи,
  Room DELETE или между commit и post-restore. Границы покрыты транзакционными и
  управляемыми recovery-тестами F03/F16.
- Реальный внешний облачный provider, отключение сети и перенос файла между двумя
  физическими устройствами не проверялись.
- S25 остаётся отдельной приёмкой.
