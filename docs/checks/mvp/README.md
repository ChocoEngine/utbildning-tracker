# Проверки MVP — 2026-09-26

Среда: macOS arm64, Temurin JDK 17.0.13, Android SDK 36 / Build Tools 35.0.0,
AVD `Medium_Phone_API_36` (Android 16). AGP 8.13.2 и Gradle 8.13 не обновлялись.
Android 13 отложен пользователем; результат API 36 не заменяет эту проверку.

## Реализовано и покрыто тестами

- S07–S09: обе формы курса, категории и их удаление, лимит/цвета, массовый
  редактор тем, сохранение ID/прогресса, конфликты, ручные отметки и жесты.
- S10–S12: чистый генератор дат, DST/границы дат, первая настройка расписания,
  горизонт 90 дней, догоняющая генерация и дальний месяц без дублей.
- S13–S17: несколько/ноль тем после занятия, исправление своего вклада,
  календарь, прошедшие пропуски, «Сегодня» и вопрос после конца/+90 минут.
- S18–S19: завершение/пауза/удаление, история, освобождение цвета,
  исчерпание тем и отказ от завершения. Room v2, миграция 1→2 без очистки.
- S20–S21: точный AlarmManager, разрешения, реальная доставка и переход,
  повторное событие без дубля; отмена после изменения курса/результата.

Проверяются файловая БД после переоткрытия, откат транзакций, настоящая
`Activity.recreate` с черновиком и восстановление локального Compose-состояния.
Сквозной сценарий данных включает 40 задач по C, несколько тем за занятие,
занятие без завершённых тем и 20 тем без расписания. Карта сценариев —
[MVP_CHECKLIST.md](../../MVP_CHECKLIST.md).

```sh
./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:connectedDebugAndroidTest --console=plain
```

Итоговый общий прогон: **BUILD SUCCESSFUL**, 13 JVM-тестов и 100
инструментальных тестов прошли; ошибок и пропусков нет. Lint: 0 ошибок /
23 предупреждения (обновления зависимостей, иконка/перенос данных,
синхронный commit, тип коллекции в Compose-state, проверка broadcast action
и рекомендации KTX). Коллекция заменяется новым экземпляром при каждом
изменении; receiver не экспортирован. Предупреждения не устранены попутным
рефакторингом.
Финальный прогон после дополнения тестов S22/S23: **BUILD SUCCESSFUL in 3m 54s**;
XML-результаты сверены (0 failures/errors/skipped). JVM-задача использовала
актуальные результаты без изменений исходников JVM-тестов.
Выборочный `ReminderNavigationTest` уже прошёл после исправления: внешний
переход после чтения Room выполняется на Android main thread при RESUMED.
В тестовом Compose-планировщике продолжение после Room иначе шло с потока БД;
первичное исключение скрывалось последующей ошибкой уничтожения back stack.

## Системные проверки уведомлений

Реальная доставка ближайшего AlarmManager и открытие нужного занятия проверены
инструментальным тестом; повторный receive не создаёт второго уведомления,
отметка результата убирает показанное напоминание. `ReminderTest` отдельно
проверяет паузу/завершение/удаление/исчерпание и раннюю отметку.
Дополнительно на API 36 выполнены реальные системные проверки:

- После обычного запуска/сворачивания и `adb reboot` точный alarm восстановился
  до открытия Activity и до запуска instrumentation. BOOT_COMPLETED был обработан
  примерно через 45 секунд после загрузки. ID занятий сохранились.
- Europe/Moscow → Europe/Berlin: местное начало 14:13 сохранилось, epoch alarm
  сдвинулся на 3 600 000 мс. После возврата пояса восстановился исходный момент.
- Перевод часов на +60 секунд сохранил один alarm с исходным временем занятия.
- `adb shell pm revoke … POST_NOTIFICATIONS` выполнен вне instrumentation:
  `allowed=false`, календарь читается и синхронизируется, ID не меняются.
- RecoveryProbeTest prepare/verify/denied/cleanup прошли отдельно от общего
  прогона. Тестовый курс удалён; часы, пояс и разрешение возвращены.

Фрагменты состояния AlarmManager — [system-checks.txt](system-checks.txt).

собранный в 14:01; исходный Kotlin-код приложения не менялся. В текущем состоянии AVD

## Сквозная приёмка и гайд — S22/S23

Финальная команда выше выполнена на API 36 **при отключённых Wi-Fi и мобильных
данных**; `dumpsys connectivity`: `Active default network: none`.
Все 14 сценариев имеют свидетельства данных, UI и системных проверок в
[MVP_CHECKLIST.md](../../MVP_CHECKLIST.md). Автоматизированные сценарии
не выдаются за ручное прохождение каждого действия; системные сценарии
проверены отдельно на эмуляторе.

- `LocalizedReminderDeliveryTest`: настоящие AlarmManager-уведомления на RU/EN,
  тексты «Пора заниматься» / «Time to study», название системного канала
  «Начало занятий» / «Course starts», пользовательское название без перевода.
- `LanguageSettingsTest`: смена языка через UI сохраняет названия курса,
  категории и тем, расписание, занятия и ручной прогресс; пересоздание Activity
  также не меняет эти данные. Системный язык/fallback проверяются этим же классом.
- Гайд сверён с реализованными курсами, категориями, редактором, жестами,
  расписанием, результатами, календарём, жизненным циклом и напоминаниями.
  Тест открывает его из настроек дважды на каждом языке, прокручивает все девять
  разделов и возвращается назад. Удержание и снятие отметки объяснены RU/EN.
- Комплекты ключей строк RU/EN совпадают. Счётчики используют нейтральные
  подписи «Занятий: N», «Завершено: N» и числовой прогресс; зависимой от числа
  формы существительного после числа нет. Даты локализуются через выбранную
  Locale; визуальные свидетельства RU/EN сохранены выше.
- После общего прогона выполнены отдельные `RecoveryProbeTest prepare`,
  `denied`, `cleanup` — каждый **OK (1 test)**. Между prepare/denied реально
  отозван POST_NOTIFICATIONS вне instrumentation, сеть оставалась отключённой.
  Синхронизация и ID занятий сохранились, холодный запуск Activity успешен,
  «Сегодня» показал проверочный курс и запланированные занятия.
  [Состояние](offline-checks.txt), [XML интерфейса](offline-today.xml).
- Проверочный курс удалён; Wi-Fi/мобильные данные включены, POST_NOTIFICATIONS
  разрешён, точный доступ возвращён в выключенное состояние контрольной точки S20.
  Debug APK установлен на эмуляторе; новая функциональность не добавлялась.

При подготовке тестов исправлен grant точного доступа на уровне UID:
после системного отказа package-level `allow` не перекрывал UID-level `deny`.
Первый прогон завершился двумя ошибками подготовки; следующий остановлен из-за
зависания совмещённого теста Compose и смены локали. Проверки доставки локалей
выделены в самостоятельный тест без Compose. Выборочный прогон 10 тестов и
последующий полный прогон 100 тестов успешны. Изменения относятся к проверкам,
Kotlin-код приложения не менялся.
