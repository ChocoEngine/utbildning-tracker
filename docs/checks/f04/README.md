# F04 — восстановление из настроек

Выполнено 2026-10-07. Восстановление доступно в настройках и использует
проверенный атомарный импорт F03; объединение копий не добавлялось.

## Реализация

- Системный picker принимает файл копии. Выбранный URI ограниченно копируется во
  внутренний временный файл и полностью проверяется до показа подтверждения;
  временный файл удаляется после проверки, постоянное право на URI не требуется.
- После успешной проверки показывается короткое подтверждение полной замены.
  Отмена picker или подтверждения не вызывает импорт. Только явное подтверждение
  передаёт уже проверенный снимок в `BackupImporter`.
- Настройки показывают отдельные результаты успеха, отмены, неверного файла и
  ошибки применения. Тексты и гайд обновлены на русском и английском.
- Импорт по-прежнему заменяет все переносимые данные: категории, курсы, темы,
  расписания, правила, календарную историю и язык. URI места хранения и права
  провайдера зависят от устройства, не входят в копию и на новом телефоне должны
  выбираться снова.

## Проверки

Из `tracker-app/` с JDK 17:

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug --console=plain
```

Результат: обе APK собраны, 33/33 JVM-теста прошли, lint — 0 ошибок.

На отдельном `ScheduleReturnFix` API 36 AVD без очистки сначала выполнено
идемпотентное заполнение 2/2, затем направленный набор:

```sh
adb shell am instrument -w \
  -e class com.utbildning.tracker.backup.BackupImportTest,com.utbildning.tracker.backup.BackupArchiveTest,com.utbildning.tracker.backup.BackupSnapshotTest,com.utbildning.tracker.ui.settings.SettingsRestoreUiTest \
  com.utbildning.tracker.test/androidx.test.runner.AndroidJUnitRunner
```

Результат: 16/16. Сквозной UI-тест подтверждает замену прежнего снимка и
восстановление темы, результата занятия, календаря, расписания и языка после
нажатия подтверждения. Проверены отказ от подтверждения, отдельные состояния
неверного файла и успеха, RU/EN тексты и обновлённый гайд. Импорт из URI также
проходит полный круг и сохраняет все переносимые поля.

На том же AVD через реальный системный picker отдельно проверены возврат Back и
выбор повреждённого `.studytracker-backup`: настройки показали соответственно
отмену и ошибочный файл, подтверждение замены не появилось. В обоих сообщениях
явно указано, что текущие данные не изменены. Временный повреждённый файл после
проверки удалён; существующие данные AVD не очищались.

## Ограничения

- Полный instrumentation-набор и Android 13 не запускались; это остаётся общей
  проверкой F17.
- Настоящее убийство процесса после commit отдельно в F04 не повторялось; граница
  и возобновление уже покрыты направленными тестами F03.
