# R02-T01 — ограничение названия темы

Проверено 2026-10-05. При явном сохранении списка название каждой темы сначала
очищается от крайних пробелов, затем ограничивается первыми 100 Unicode code
points. Ввод и вставка остаются неограниченными. Обрезка не разрывает UTF-16
surrogate pair.

## Изменения

- Единая нормализация находится в `TopicListEditor.normalizeTitle` и используется
  текстовым парсером и публичным созданием курса из `List<String>`.
- Правило действует при создании курса через текстовый список, прямом создании
  через репозиторий и применении редактора тем.
- После применения ViewModel повторно читает темы из репозитория, поэтому редактор
  показывает фактически сохранённый текст.
- Конфликты с пройденными темами проверяются после нормализации редактируемых строк
  и сохраняют исходные номера строк. Транзакция не записывает часть метаданных,
  категории или тем при конфликте.
- Совпавшие после обрезки редактируемые темы остаются отдельными строками и получают
  разные ID. Неизменённые темы сохраняют ID и прогресс; пройденные темы не
  нормализуются при открытии или сохранении других полей.
- Схема Room и миграции не менялись.

Из `tracker-app/` с JDK 17 и Android SDK из README выполнено:

```text
./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest --console=plain
BUILD SUCCESSFUL
lint: 0 errors, 35 warnings
JVM: 33/33
```

Направленный прогон `TopicListRepositoryTest`, `CourseFormRepositoryTest` и двух
UI-сценариев прошёл: 23/23. После последнего изменения только визуального ожидания
RU-сценарий с настоящей вставкой из Android clipboard повторён отдельно: 1/1.

Покрыты границы 99/100/101 code point, строка из 10 000 supplementary-символов,
кириллица, emoji вне BMP, смешанный текст, trim до ограничения, независимые строки,
пустые строки и исходные номера, оба пути создания, применение, прямые публичные
вызовы репозитория, повторное сохранение, отмена, сохранение ID/прогресса и
пройденных тем, конфликт после обрезки без частичной записи и одинаковые итоговые
названия без объединения.

Полный API 36 instrumentation запускался из-за изменения общего пути сохранения.
Лучший полный прогон выполнил 193 теста: 192 прошли, один старый календарный
UI-сценарий не нашёл ленивый элемент на высоте 540 dp; тот же тест отдельно на
стандартной высоте прошёл 1/1. Повторный чистый полный прогон на стандартной высоте
оказался нестабилен: 10 старых UI-падений, начиная с восстановления Activity, затем
каскад в общих экранных сценариях. Новые R02-T01-тесты в полных прогонах прошли.
Поэтому полный instrumentation не объявляется зелёным.

эмулятор не запускался, его приложение и данные не очищались и не переустанавливались.

открытие сохранённого смешанного названия с supplementary Unicode. Оба снимка
