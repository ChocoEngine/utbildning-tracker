# R05 — функциональная и визуальная приёмка

R05 выполнен 2026-10-06 на отдельном API 36 AVD, RU/EN, 320 × 540 dp.
Подтверждены и исправлены два дефекта редактора: сохранение активных полей при
уходе в фон и перекрытие действий диалогов клавиатурой. Сценарии ниже пройдены,
снимки сохранены и просмотрены. Приложение готово к пользовательской проверке R06.

Полный набор **не объявляется зелёным**: 198 случаев, один таймаут
возврата из расписания; тот же сценарий отдельно прошёл. Таймаут повторился в прогоне класса. Его причина не установлена; замечание
к стабильности instrumentation остаётся открытым.

## Ревизия и окружение

- Исходная ревизия `e206520ae587de6be84f2b4d60821e5b8757d021`; итог — эта ревизия
  с незакоммиченными исправлениями R05, тестами и документацией.
- Прежние неотслеживаемые логи QA-001 сохранены. Commit/push, обновление зависимостей,
  общий рефакторинг, S25 и новые функции не выполнялись.
- JDK 17.0.13, Gradle 8.13, закреплённый SDK Platform 36 / Build Tools 35.0.0.
- Android Emulator 36.4.10.0, AVD `Medium_Phone_API_36`, фактический serial
  `emulator-5556`, API 36, density 420, timezone Europe/Moscow.
- Cold boot с `-no-snapshot`, без wipe. Пользовательский `Pixel_6` не запускался.
  Все команды adb для устройства содержат `-s emulator-5556`.
- Основной экран `840 × 1418 px` при density 420: `320 × 540 dp` с округлением пикселя;
  дополнительный стандартный экран `1080 × 2400 px`.
- На тестовом AVD включено `show_ime_with_hard_keyboard=1`. RU/EN интерфейса
  проверяются отдельно; пользовательские названия не переводятся.

## Подтверждённые дефекты и исправления

### R05-001 — активные поля не сохранялись при уходе в фон

1. Открыть сохранённый курс C, удержать заголовок, ввести новое имя.
2. Не менять фокус; остановить Activity переходом в фон.
3. Проверить Room до возврата приложения.

Ожидалось сохранение введённого имени. Фактически БД сохраняла прежнее имя;
[воспроизводящая проверка](logs/background-before-runner.txt) завершилась
`Active field was not stored while Activity was stopped`.

В `CoursesScreen` добавлен обработчик ON_STOP; `CoursesViewModel.saveOnBackground`
сохраняет снимок полей существующего курса через прежнюю очередь записей.
Экран не закрывается, первичный несохранённый диалог не создаёт курс,
неприменённые темы не записываются. Регрессия проверяет имя, категорию и сохранение
черновика тем после реального перехода Activity CREATED → RESUMED.

### R05-002 — клавиатура перекрывала действия диалогов

1. На 320 × 540 dp открыть длинный список тем в настоящей MainActivity.
2. Коснуться поля и открыть Gboard.
3. Попытаться применить или отменить текст.

Ожидались доступные кнопки над клавиатурой. Фактически поле занимало всю видимую
высоту, кнопки были за IME, заголовок заходил под status bar.
[Реальный экран до исправления](screenshots/main-topics-before.png).
`assertIsDisplayed()` при этом мог проходить и не доказывал видимость пикселей.

Диалоги ввода названия/категории/тем явно учитывают IME и системные отступы.
Список тем остаётся прокручиваемым; правила сохранения и Unicode не менялись.
Первичная форма получила прокрутку полей. Дополнительный просмотр подтвердил,
что при IME заголовок занимал место локализованной ошибки длины:
[RU до](screenshots/creation-error-before-ru.png),
[EN до](screenshots/creation-error-before-en.png). Заголовок первичного окна
теперь скрывается только при открытой IME; закрытая клавиатура возвращает его.
Правила текста/выделения сохранены. Полное сообщение видно над IME:
[RU после](screenshots/editor/ru_creation_name_error_keyboard.png),
[EN после](screenshots/editor/en_creation_name_error_keyboard.png); в окне категории убран дублирующий
заголовок, чтобы поле не сжималось и не обрезало текст при IME.
Проверяется положение действий в AccessibilityWindow относительно настоящего
окна IME, затем отмена тем и очистка категории выполняются инъекцией сенсорных
событий по экранным координатам кнопок. RU/EN снимки просмотрены отдельно. На настоящей MainActivity с Gboard обе кнопки
видны над IME: [после исправления](screenshots/main-topics-after.png).

При очистке категории меню совпадений также перекрывало применение:
[до исправления](screenshots/category-popup-before.png). Теперь пустой ввод
сворачивает меню; выбор существующей категории через раскрытие остаётся доступен.

### Ошибки подготовки проверок

- Новая проверка высоты ошибки первичной формы сначала требовала две строки;
  EN-сообщение на этом экране полностью помещается в одну. В промежуточном
  прогоне это дало один ложный failure. Минимальная высота исправлена на 10 dp,
  чтобы обнаруживать прежнее обрезание до нескольких пикселей; текст целиком
  дополнительно просмотрен на RU/EN PNG. Проверки текста/выделения не удалены.

- Первая background-проба не ждала появления редактора:
  [лог](logs/background-probe-missing-wait.txt). Исправлено ожидание целевого узла.
- Ожидание Compose-кадров у остановленной Activity зависало:
  [прерванный лог](logs/background-probe-stopped-compose.txt). В фоне БД проверяется
  платформенным polling, Activity возвращается в RESUMED в finally.
- Первая EN-фикстура содержала 51 code point; репозиторий правильно отказал
  с NAME_TOO_LONG. Название теста заменено допустимым; начальный узкий прогон
  [прерван](logs/narrow-initial-aborted-runner.txt), он не считается завершённым.

- Узкий прогон 79 сценариев: 2 failures, 705.205 s,
  [лог](logs/narrow-final-runner.txt). Ошибки ожидания открытия создания и attach
  созданного курса исправлены точечно в AppNavigationTest и CoursesScreenTest;
  лимиты времени не увеличены. Это промежуточный результат, а не зелёная приёмка.
- Синтетические RU диалоги наследовали EN ресурсы тестового окна; добавлен явный
  LocalResources. Захват topic_editor исправлен с фона на окно Dialog. Старые
  ошибочные снимки не используются как доказательство правильного диалога.

## Снимки и просмотр

Все сохранённые значимые состояния просмотрены через PNG и контактные листы;
для повторяющихся имён выбраны последние снимки соответствующего прогона.
[Индекс снимков](screenshots/README.md) содержит прямые RU/EN ссылки.
Синтетические локализованные окна проверяют отображение на реальном Compose/IME;
настоящие MainActivity/Home/Room подтверждены отдельно. Даты 25–26 сентября
в синтетических сценах фиксированы тестами и не означают дату проверки.
На 320 dp создание с IME прокручивает поля: название и категория могут
быть за границей видимой области после прокрутки к другому полю; кнопки остаются
доступны. Последнее локальное исправление скрывает заголовок при IME и сохраняет
полное сообщение ошибки рядом с именем; закрытая IME возвращает заголовок. Редактор списка тем прокручивает текст; частично видимая строка у края
viewport не считается обрезанным сохранённым названием.
