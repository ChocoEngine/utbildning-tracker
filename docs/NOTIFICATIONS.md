# Уведомления MVP (S20–S21)

Перед реализацией проверены официальные документы Android:
[AlarmManager](https://developer.android.com/develop/background-work/services/alarms)
и [POST_NOTIFICATIONS](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

Для неотмеченного занятия приходят напоминания в момент начала и в момент
вопроса о результате: в заданное время окончания либо через 90 минут после
начала, если окончание не задано. Используем `AlarmManager` с
`setExactAndAllowWhileIdle(RTC_WAKEUP)`, immutable PendingIntent и явным receiver.
Не используем периодический опрос вместо точной доставки. Одновременно
зарегистрирован один ближайший alarm любого из двух типов; при его срабатывании
показываются напоминания всех актуальных занятий с этим временем и назначается следующий.
Это не превышает системный лимит количества alarm при большом календаре.

Для новых установок нужны runtime POST_NOTIFICATIONS и специальный доступ
SCHEDULE_EXACT_ALARM. Настройки приложения предлагают включить уведомления
и открыть системный экран точных напоминаний. При отказе календарь работает;
неточные напоминания не включаются скрыто. Состояние показано в настройках.
Даже с доступом доставка зависит от ограничений Android/производителя;
выключенное устройство и force-stop не позволяют гарантировать напоминание.
Без разрешения точных alarm уведомления не планируются.

При возврате приложения, изменении сессий/курсов, boot, смене времени/пояса
и выдаче доступа alarm выполняются догоняющая генерация и сверка. Receiver
перед показом перечитывает актуальное занятие/курс: PENDING, курс активен,
есть расписание, темы не исчерпаны; дата/время всё ещё совпадают с alarm.
Пропущенное из-за выключенного устройства напоминание не приходит сильно позднее:
доставка допускается в пределах 5 минут после запланированного события.
Уже показанные типы событий и ID сохраняются локально для защиты от повторного
broadcast. Старые сохранённые ID начала совместимы с предыдущей версией приложения.

Пауза/завершение/удаление/исчерпание/ранняя отметка результата пересчитывают
ближайший alarm и убирают уже показанные неактуальные уведомления. При
совпадающем времени занятий разные ID сохраняют отдельные уведомления.
Нажатие на тело любого из двух напоминаний открывает экран выбранного занятия через
explicit immutable Activity `PendingIntent` и само по себе не записывает результат.
Только вопрос о результате содержит две кнопки. «Пройдено» открывает Activity напрямую:
для курса с темами — выбор фактически завершённых тем, для курса без тем — атомарная
запись `DONE` без пустого экрана выбора. «Пропущено» обрабатывается явным receiver,
атомарно записывает `SKIPPED` без открытия Activity и без изменения тем. После успешной
записи уведомление отменяется и расписание напоминаний пересчитывается; при ошибке
уведомление не удаляется как успешно обработанное.
У тела, обеих кнопок и каждого `sessionId` разные identity `PendingIntent`; extras не
используются как единственный идентификатор. Повторная доставка и действие из
устаревшего уведомления применяются только к всё ещё `PENDING` занятию и не
перезаписывают уже выбранный результат.
Если вопрос пришёл после полуночи, занятие с датой начала вчера остаётся редактируемым;
позавчерашнее занятие открывается только для просмотра.
На редактируемом экране доступны оба ответа — «Пройдено» и «Пропущено»; обычный
экран по-прежнему позволяет исправить ранее записанный результат по правилам даты.
Локаль следует настройке приложения; название курса не переводится.

## Проверка

Обычные доставка, reboot и отзыв/возврат разрешений фактически проверены на API 36
и API 33 в [отчёте повторной ревизии](checks/repeat-review-fixes/README.md).
Завершение R03 на API 36, реальные действия шторки и ограничения —
[итоговый отчёт](checks/r03-final/README.md). Ночное ожидание и действия шторки
на API 33 отдельно не повторялись; все поддерживаемые устройства не объявляются проверенными.

## Реализованное уточнение 2026-10-05 — R03-N01

Неотмеченное занятие остаётся PENDING в дату начала и следующий день, даже
если календарь уже отображает пропуск. Поэтому вопрос в окончание ночного
занятия либо +90 минут после начала остаётся актуальным после полуночи.
Синхронизация до доставки и сразу после показа не должна отменять такой
вопрос или блокировать быстрые действия. Явный ответ сразу отменяет
неактуальные уведомления. С даты начала +2 дня окно закрыто: синхронизация
ставит SKIPPED, устаревшие действия не применяются, уведомления удаляются.
Фильтрация действий учитывает фактический результат и текущую локальную
дату даже до очередной синхронизации. Политика 5 минут и защита от дублей
не меняются. Первоначальные проверки — [отчёт R03-N01](checks/r03-n01/README.md).
Позднее реальные ночные question alarm 23:30→01:00 и +90 минут прошли на API 36
в [повторной ревизии](checks/repeat-review-fixes/README.md). Обе кнопки системной
шторки, включая выбор тем после «Пройдено», проверены на API 36 для RU/EN,
сегодня/вчера и курсов с темами/без тем при [завершении R03](checks/r03-final/README.md).
