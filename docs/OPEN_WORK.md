# Открытая работа и проверки

Актуально на 2026-10-22 для `codex/version-02` и её продолжения. Здесь только
незавершённое или не подтверждённое на будущей итоговой ревизии. Выполненные
MVP, F01–F17, PERF и R01–R06 не образуют повторную очередь. R06 закрыт после
проверки пользователя на личных курсах; следующая версия проверяется заново.
Результаты старых прогонов кратко сведены в [проверенной базе](VERIFICATION_BASELINE.md)
и доступны подробно в Git-истории; они не переносятся автоматически на
изменённую сборку.

Порядок: **L04–L05 → R07 → полная проверка пользователя → S25**.
S25 запускается только по отдельному запросу после приёмки следующей версии.
Коммит, push, tag и публикация — по отдельному запросу.

## 1. Завершить реализацию

- [ ] **L04 — свойства календарных правил.** Дополнить JVM-тесты генератора,
  пересечений, местных дат и срока хранения недостающими независимыми
  свойствами: месяцы/годы, високосные дни, ночные интервалы, пояса и DST,
  отсутствие дублей, включительная граница конца и срока хранения. Каждый
  сбой воспроизводится по seed; обычный набор ограничен по времени.
- [ ] **L05 — упорядочить настройки и «Как пользоваться».** Сгруппировать
  действующие пункты настроек понятным пользователю образом и убрать повторные
  пояснения, сохранив доступность всех действий. Переписать RU/EN-гайд
  короткими разделами: курс, темы, расписание, результат, пауза/завершение,
  копия/восстановление. Сохранить предупреждения о полной замене данных,
  удалении истории при перезапуске и очистке; не обещать точное время фоновых
  задач и не менять правила копирования, восстановления и очистки. Проверить
  строки, сборку/lint и визуально оба экрана RU/EN на узком устройстве с
  клавиатурой и крупным шрифтом.

Для каждой задачи: записать ревизию, изменённые файлы, команды, результат и
непроверенное. Отметка `[x]` означает выполненный критерий, а не только наличие
кода. Если поздние проверки уже покрывают пункт, приложить точную ссылку на
доказательство и не повторять прогон без причины. Продуктовые правила — в
[ТЗ](PRODUCT_SPEC.md); формат копии — в [контракте](BACKUP_CONTRACT.md).

## 2. R07 — инженерная стабилизация итоговой сборки

- [ ] Зафиксировать ревизию-кандидат, состав изменений, `versionCode` и
  `versionName`; не смешивать результаты разных APK.
- [ ] На JDK 17 и SDK 36 выполнить из `tracker-app/`:

  ```sh
  ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug --console=plain
  ./gradlew :app:connectedDebugAndroidTest --console=plain
  ```

  Полный instrumentation запускать на отдельном тестовом AVD. Записать API,
  размер, локаль, успехи, failures и assumption-пропуски. Пропуск не считать
  успехом; каждый failure разобрать, исправить и повторить затронутый сценарий.
- [ ] Проверить итоговую сборку на API 36 и Android 13/API 33 в заявленном
  объёме. Ночное ожидание, реальный reboot, отзыв/возврат разрешений и действия
  системной шторки фиксировать отдельно от обычного полного прогона. Старые
  результаты API 33 не засчитывать новой сборке автоматически.
- [ ] Установить APK **поверх** предыдущей версии на тестовом устройстве без
  удаления приложения и сброса БД. Проверить миграцию и сохранность курсов,
  категорий, тем, прогресса, занятий, расписаний, языка, настроек очистки и
  копирования. Разрушительный импорт проверять на тестовых данных.
- [ ] Повторить на итоговой сборке ключевые пути: сегодня/вчера, прошлая
  конечная дата, ночное окончание, начало и вопрос об итоге, действия шторки,
  отсутствие дублей после холодного запуска. Реальную доставку считать
  проверенной только после ожидания и действия, а не после регистрации alarm.
- [ ] Обновить [сводку проверок](VERIFICATION_BASELINE.md): ревизия, окружение,
  команды, результаты, непроверенные сценарии и подтверждённые дефекты.
  Закрыть R07 только при успешных инженерных проверках, сохранности данных при
  обновлении и отсутствии подтверждённых критичных дефектов основных сценариев.

## 3. Независимая полная проверка пользователя

Проводится **после** U/L и R07 на конкретной переданной сборке. Проверка R06
относилась к прежней версии и не заменяет этот этап.

- [ ] Передать APK, ревизию, номер версии, перечень изменений и ограничения;
  записать установленную сборку и устройство/API.
- [ ] На личных курсах проверить создание и редактирование, категории, темы,
  расписание/конечную дату, отметку и исправление занятия, календарь,
  паузу/продолжение, язык и гайд. Перезапуск завершённого курса и
  восстановление с полной заменой данных проверять на отдельной базе либо
  после сохранённой копии и явного выбора пользователя.
- [ ] Проверить несколько реальных занятий, включая уведомление и ночное
  занятие либо оставленное до следующего дня. Записать фактически выполненное,
  ожидание, результат и замечания; пропущенные случаи оставить непроверенными.
- [ ] После исправления замечания передать новую сборку, повторить затронутый
  сценарий и получить явное подтверждение пользователя для этой версии.

## 4. S25 — отложенная доступность

До полной пользовательской проверки следующей версии S25 не начинать.
После отдельного запроса в изолированной ветке/checkout проверить и при
необходимости исправить:

- [ ] TalkBack на всех экранах, диалогах и списках: понятные имена, роли,
  состояния и порядок фокуса. Прогресс озвучивать как число завершённых тем,
  а у курса без тем — занятий; день календаря — с полной датой, выбором и
  кратким содержимым, строку занятия — с курсом, временем и результатом.
  Ошибку ввода связать с полем; после диалога возвращать фокус к действию или
  ближайшему логическому элементу. Цвет не должен быть единственным сигналом.
- [ ] Именованные действия темы без удержания для TalkBack/Switch Access и
  клавиатурный Enter/Space с одним изменением на нажатие, без переключения от
  автоповтора. Обычный короткий тап не отмечает тему; долгое касание остаётся,
  прокрутка его отменяет. Категории и календарь доступны без сложных жестов.
- [ ] Зоны нажатия от 48×48 dp без перекрытия, включая календарную сетку,
  карандаш категории, удаление даты, цвета и кнопки диалогов. Проверить
  100/150/200% шрифт и увеличенный системный размер на узком экране с IME:
  текст не перекрывает действия, диалоги прокручиваются, кнопки достижимы.
- [ ] Контраст текста не ниже 4.5:1, крупного текста и важных графических
  элементов не ниже 3:1; состояния различимы без цвета.
- [ ] Автоматические регрессии именованных действий темы, календарного дня и
  категории с тем же результатом данных, что при обычном взаимодействии.
  Вручную пройти RU/EN с TalkBack и отдельно клавиатурой/Switch Access:
  курс, категорию (добавление без выбора, выбор, удаление), расписание,
  календарь, отметку темы и занятия, подтверждение/отмену завершения, язык
  и гайд. Проверить API 36 и минимальный API 33 либо явно оставить API 33
  непроверенным. В [сводке](VERIFICATION_BASELINE.md) записать устройство,
  версии сервиса, язык, масштаб, сценарии, контраст и ограничения; при
  необходимости приложить новые снимки.

S25 не является условием закрытия R07. Существующую доступность не ухудшать.
