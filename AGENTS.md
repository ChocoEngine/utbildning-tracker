## Как начинать новый чат

При запуске эмулятора наполнять его тестовыми данными, сохраняя существующие пользовательские данные и прогресс. Использовать повторяемое заполнение без дублей: курсы с расписанием, без расписания и завершённый, занятия за прошедшие дни с разными результатами. Для визуальной проверки календаря сохранять примеры с четырьмя разными цветами (два занятия пройдены, два нет) и с пятью курсами (один день с пройденным занятием, другой — без пройденных). Если пользователь явно просит запуск без заполнения, следовать этому указанию.

Незавершённая текущая задача: [передача переработки редактора курса](docs/COURSE_UI_HANDOFF.md). Пользователь попросил оставить возвращённые изменения и остановиться; продолжение только по следующему заданию. Перед работой над этим UI прочитать передачу и требования, не откатывать рабочий diff целиком.

Приоритет продолжения — U00: пользователь сообщил, что задание расписания сейчас совсем не работает. Причина ещё не исследована; воспроизвести и исправить первую настройку для нового и существующего курса, проверить сохранение и создание занятий. Подробности в передаче задачи; это не запрос реализовать отложенную замену расписания.

1. Прочитай этот файл: здесь краткий контекст, состояние проекта и ключевые решения.
2. Для текущей задачи прочитай соответствующий раздел [MVP_PLAN.md](MVP_PLAN.md) или [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). Не перечитывай все документы без необходимости.
3. Проверяй только относящиеся к задаче файлы и зависимости. Не делай полный обзор кода заново, если карта проекта и состояние ниже актуальны.
4. Сведения о реализации сверяй с затрагиваемым кодом: база знаний помогает ориентироваться, но не заменяет проверку перед изменениями.
5. Явные указания пользователя для текущей задачи имеют приоритет. Не расширяй объём функций без запроса.

Команды «Начни MVP» и «Выполни следующий незавершённый шаг MVP» запускают один первый незавершённый шаг из чек-листа MVP_PLAN.md. Сначала прочитать раздел «Как выполнять план»: стек, локализация, проверки, сохранение посторонних изменений и обновление статусов обязательны без повторения в промпте. Частично выполненный шаг продолжать с оставшейся работы; после выполнения обновить чек-лист и этот файл. Не переходить к следующему шагу без запроса на больший объём.

## Назначение и ограничения

Android-трекер самостоятельного прохождения онлайн-курсов. Мотивация — красиво заполненный календарь и видимый прогресс.

- Данные на телефоне, SQLite через Room.
- Нет сервера, логина и привязки к сайтам курсов.
- Несколько курсов с отдельными цветами и расписаниями, группировка по категориям.
- Не добавлять заметки, достижения, награды, серии занятий и специальную механику домашних заданий.
- Домашняя работа — обычный курс: свободная практика без тем или именованные задачи как список тем. Отдельного числового счётчика задач нет. Можно группировать с лекциями в одной категории, автоматической связи между ними нет.
- В обсуждениях, документации и макетах использовать C как пример языка программирования для учебных курсов.

## Ключевые продуктовые решения

- В MVP русский и английский интерфейс. В настройках выбор «Как в системе», «Русский», «English»; по умолчанию системный язык, для неподдерживаемого — английский. Выбор сохраняется после перезапуска. Все тексты, уведомления и подписи доступности хранить в ресурсах локализации; даты и множественные формы учитывать для выбранного языка. Пользовательские названия курсов, категорий и тем не переводить. Смена языка не меняет расписание, часовой пояс и прогресс.
- Курс: название, цвет, категория, необязательные темы, статус завершения.
- В S07 реализовать удаление категорий корзиной в выпадающем списке: пустые сразу, с курсами (включая завершённые) — после подтверждения. Курсы остаются без категории, их данные сохраняются. Удаление независимо от сохранения формы; выбранную удалённую категорию сбросить в черновике. Дополнение репозитория и проверки входят в S07, статус выполненного S05 не означает реализацию этого нового требования.
- Категория задаётся редактируемым полем с выпадающими подсказками. При сохранении курса точное совпадение без учёта регистра/крайних пробелов выбирает существующую категорию, иначе новая создаётся в той же транзакции без подтверждения. Пустое поле — без категории; отмена не создаёт категорию. Изменение поля не переименовывает общую категорию других курсов.
- Палитра: 10 спокойных цветов, уникальных среди незавершённых курсов. Показывать свободные цвета и собственный текущий. Завершение и удаление освобождают цвет сразу; история сохраняет прежний цвет.
- Максимум 10 незавершённых курсов, включая курсы без расписания и на паузе. При лимите скрыть добавление курса и запретить создание при сохранении.
- В MVP два режима, выбор при создании: «По расписанию» (темы необязательны) и «Без расписания» (нужен непустой список тем).
- Без расписания: вручную отмечать любую тему пройденной и снимать отметку; прогресс по темам. Нет календарных записей, пятнышек, уведомлений и вопросов о занятиях. После прохождения всех тем предложить завершить курс. Очистка календаря не удаляет такой список.
- Расписание: дни недели и время начала для каждого дня; окончание занятия и конечная дата необязательны.
- Результаты занятия: «Пройдено», «Пропущено», «Без отметки». Их можно исправлять. В конце дня неотмеченное занятие автоматически становится пропущенным.
- С расписанием и темами: после «Пройдено» выбрать галочками любое количество непройденных тем, в том числе не по порядку, либо «Позанимался, но пока ничего не завершил». Яркость пятнышка отражает факт занятия, прогресс курса — только завершённые темы.
- Календарь показывает название курса и время. Темы по датам не распределяются: нет темы-ориентира, предварительных назначений или автоматического переноса. После занятия пользователь выбирает фактически пройденные темы, включая несколько лекций за раз.
- Прошедшие занятия сохраняют результат и связи с завершёнными темами. Пропуск, отсутствие отметки и занятие без завершённых тем не закрывают темы и не перераспределяют будущий план.
- В календаре сегодняшние и будущие занятия без результата подписываются «В плане». С началом следующего дня неотмеченные занятия становятся пропущенными; вчерашний результат исправляется в блоке «Вчера» экрана «Занятия», календарь остаётся без действий.
- Календарь: клякса под датой, несколько занятий — полосы цветов курсов; без результата бледные, пройденные яркие, пропущенные бледные с крестиком.
- Список курсов компактный, в стиле календаря: цвет, название, прогресс; нажатие открывает редактирование. По умолчанию незавершённые, внизу общее число завершённых и переключатель «Показать все» / «Показать незавершённые».
- Без тем: отмечается факт занятия, прогресс — количество пройденных занятий, без процента.
- Непройденные темы можно добавлять, удалять и переставлять; пройденные сохраняются в истории.
- Список тем прокручивается без «Показать все»; в незавершённом курсе любого режима только долгое нажатие переключает прохождение, второе снимает отметку. Прокрутка отменяет жест. Ручная отметка не создаёт занятие.
- При вставке списка совпадения с пройденными темами без учёта регистра/крайних пробелов блокируют применение и сохранение; показать номера конфликтующих строк, ничего не удалять автоматически.
- Настройка дней и времени открывается кнопкой «Настроить» в блоке расписания.
- Темы редактируются единой кнопкой «Редактировать список» в текстовом блоке: одна непустая строка — одна тема, доступны вставка целого списка, перестановка и удаление строк. В существующем курсе пройденные темы вне редактируемого блока; прогресс и идентификаторы неизменённых тем сохраняются. Есть применение и отмена; поштучные кнопки не нужны.
- Уведомления приходят в момент начала занятия и, если результат ещё не задан, после окончания либо через 1,5 часа после начала. Нажатие открывает занятие; позднее начало после вопроса не дублируется.
- Вопрос «Получилось позаниматься?» — карточка на экране «Занятия» после заданного окончания или через 1,5 часа после начала. Ответы: «Пройдено» / «Пропущено». Без модального окна; в тот же момент приходит уведомление о результате.
- На экране «Занятия» показывать занятия с датой начала сегодня и вчера в отдельных независимо прокручиваемых блоках; позавчера и раньше не показывать. На границе дня ставить вчерашним `PENDING` пропуск; при запуске приложения выполнять догоняющую обработку. Вчерашний результат можно исправить, результат сегодняшнего — указать раньше появления вопроса.
- После последней темы предложить завершить курс. При отказе оставить активным, но не планировать новые занятия до добавления тем или настройки расписания заново.
- Конечная дата расписания сама по себе курс не завершает.
- Ручное завершение отмечает все темы пройденными; все занятия, начавшиеся к моменту завершения, становятся пройденными, включая ранее пропущенные; все будущие занятия удаляются. Расписание и уведомления отключаются, цвет освобождается. Курс остаётся до ручного удаления. Дополнение про результаты занятий согласовано 2026-10-02, но в текущем коде ещё не реализовано; выполнить в R02.
- Удаление с подтверждением убирает курс, темы, календарь и уведомления, освобождает цвет.
- Простая пауза входит в MVP: убрать расписание, будущие занятия и уведомления, сохранить прошлые занятия и прогресс. Курс остаётся незавершённым и занимает цвет; оформление паузы в списке обсудить позже.

- Редактор: не показывать «текущий цвет выбран», «Курс ещё не завершён» и постоянную подсказку о долгом нажатии. Завершение, пауза и удаление оформлены одинаково; подтверждения компактные. Гайд по приложению подготовить в конце разработки.

## После MVP — не реализовывать заранее

- Оформление паузы в списке и возобновление; перенос одного занятия без изменения недельного правила.
- Перезапуск завершённого курса: после явного предупреждения удалить все старые занятия, сбросить прохождение тем, сохранить сам курс и список тем, не восстанавливать расписание автоматически. В начале задачи обязательно отдельно согласовать цвет и сочетание с лимитом 10. Возможность предложить создание копии курса перед сбросом — отдельная будущая идея, не часть F12.
- Переключение между списком тем без расписания и курсом по расписанию. При отключении расписания сохранять прошлые занятия, их результаты, связи с темами и прогресс; удалять будущие занятия без отметки и отключать уведомления. Переключение реализовано с сохранением прогресса в обе стороны; включение выполняется при сохранении формы расписания.
- Ежедневная очистка календаря по единому скользящему сроку для всех курсов, без разделения на активные, приостановленные и завершённые. В настройках задаётся количество сохраняемых дней; удаляются занятия с локальной датой начала старше этого срока. Статус курса, просмотр и последнее изменение на границу не влияют. Значение по умолчанию, диапазон и возможность отключения согласовать в начале F15.
- После очистки остаются курс, темы с их прохождением и расписание; отдельная итоговая статистика не создаётся. F16 выполняется ежедневным периодическим WorkManager-воркером и не обещает точный час запуска.
- Резервные копии вручную и раз в неделю, выбранное место хранения, статус последней копии. Восстановление полностью заменяет данные после подтверждения, без объединения.

## Архитектурные ориентиры и проверки

- Разделять правило повторения, конкретное занятие и тему.
- В схеме v2 история `session_topic_history` отделена от текущего источника `topic_completions`. DAO — только хранение; S05 реализует транзакции курсов/категорий и резервов цветов. S06 архивирует удалённые строки, исключает архив из редактора и повторно проверяет конфликты с прохождением при сохранении. Ручное прохождение, результаты, расписание и жизненный цикл выполняются транзакциями репозитория; прошлые снимки сохраняются. Не использовать историю для автоматического восстановления снятых отметок.
- Прохождение темы может существовать без занятия; для ручных отметок в курсе без расписания не создавать фиктивные календарные записи.
- Одно занятие связано с нулём, одной или несколькими фактически завершёнными темами; планового назначения темы нет. При исправлениях не дублировать прогресс и не сбрасывать темы других занятий.
- Бессрочный календарь пополнять на ограниченный горизонт без дублей.
- Изменять результат занятия и прохождение темы согласованно.
- Проверять исправления прошлых отметок и отметки не по порядку, границы дат, исчерпание тем и конечную дату расписания.
- Уведомления должны соответствовать актуальному календарю и отменяться при удалении или завершении курса.
- Проверять сохранение данных после перезапуска, работу без сети, отказ в разрешении на уведомления и перезагрузку устройства.
- Проверка из `tracker-app/`: `./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:connectedDebugAndroidTest --console=plain`, JDK 17, SDK Platform 36 / Build Tools 35.0.0. Устройство — `Medium_Phone_API_36` (Android 16). Текущие числа тестов, результаты и ограничения — [отчёт MVP](docs/checks/mvp/README.md), условия запуска — [tracker-app/README.md](tracker-app/README.md). Не выдавать промежуточный выборочный прогон за итоговую проверку всей сборки. Есть тесты файловой БД, миграции 1→2, сохранения черновика при настоящем пересоздании Activity и восстановления выбора тем/расписания.
